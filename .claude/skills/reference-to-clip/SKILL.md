# Reference → Clip: новый клип в стиле образца

На входе клип-образец (стиль) и заказчик со своей историей. На выходе новый клип про бренд заказчика в том же стиле, сочинённый вместе с ним раундами. Этот навык — точка входа: порядок работы, контрольные точки, форматы файлов. Детали этапов — в навыках-модулях (для FRACTERA: fractera-song — песня и её замер; fractera-lego-motion — визуальный стиль и движок рендера).

## Правила
1. Стиль, а не клон. Из образца берём приёмы, пропорции, ритм монтажа и типы блоков. Слова, мелодию, аранжировку, кадры, персонажей и логотипы образца в результат не переносим. Слова образца не храним — только пересказ смысла строки и тайминг.
2. Образец присылает человек файлом. Ссылку на YouTube используем только для названия и титров: правила YouTube запрещают скачивать ролики без его собственной кнопки скачивания.
3. История и слова — заказчика. Его фразы, фрагменты и произношение сохраняем дословно и не перефразируем; мы предлагаем, он утверждает.
4. Песня первична: картинку режем под готовый трек. Но сцены и слова согласуем до генерации музыки.
5. Ничего дорогого до утверждения: музыка — после заморозки раскадровки, рендер — после утверждённого аниматика.
6. Агент не слышит звук и не смотрит видео потоком: о звуке судит по замерам, о видео — по кадрам. Вывод без замера помечается как гипотеза; то, что можно услышать только ухом, спрашиваем у человека.
7. Картинка собирается детерминированным кодом из шаблонов блоков: текст, бренд и герой всегда точные. Видеомодели — только для редких кинематографичных вставок.
8. Общий вид и качество задают подключённые наборы правил (качество движения, стиль проекта, песня, бренд); при конфликте действует порядок из раздела «Подключаемые наборы правил».

## Термины
- Образец — клип, чей стиль берём.
- Бриф — площадка и формат (16:9 / 9:16), длительность, язык, голоса, бренд-слово, аудитория, обязательное и запрещённое, бренд-гайды.
- Интервью — история заказчика, ценность, которую должен вынести зритель, тезисы, фрагменты слов и их произношение.
- Библия стиля — режимы, палитра, шрифты, словарь движений и переходов, плотность текста, тон юмора, список «что не копируем».
- Блок — повторно используемый шаблон сцены из образца. Один блок может стоять в ролике несколько раз (вариации в припевах).
- Сцена — экземпляр блока в нашем ролике, с нашими словами и параметрами.
- Раскадровка — таблица сцен по форме песни; лента — та же раскадровка одной картинкой: кадры блоков по порядку с номерами сцен и черновыми словами.
- Аниматик — черновой ролик целиком: заглушки сцен под настоящую песню.
- Таймлайн — список сцен с тактами и параметрами; это и есть монтаж в виде данных.
- Shorts — вертикальные нарезки готового клипа для публикации.

## Разбор блока: уровни, шаги, файлы, теги

Уровни описания:
| Уровень | Что внутри | Когда |
| --- | --- | --- |
| Паспорт | один кадр + строка «что видим» | при нарезке, для всех |
| Карточка | теги по словарю, смысл в песне, движение в 2–3 строках, что заменяемо, сложность | до раскадровки, для всех: по ней выбираем блоки |
| Чертёж | покадровая разметка 4–10 кадров/с: слои, тайминги в тактах и долях, движения, шрифты и цвета, синхрон с голосом, вход и выход, план сборки | перед сборкой сцены, только для блоков из раскадровки |
Чертёж делаем так: кадры блока с запасом 1 с на вход и выход, на каждом подпись «время трека + такт.доля», склеить в листы и сложить с картой голосов. Именно на этом уровне видны правила вроде «петля длиной в такт» или «картинку ведут слова, а не такт».

Имена и хранение:
- id блока = NN-slug: NN — двузначный порядковый номер в образце, slug — 2–4 английских слова через дефис (30-bot-on-pedestal). Если образцов несколько — префикс образца: lgtm/30-bot-on-pedestal.
- Вариация — свой id и поле variant_of (55-board-of-bots → variant_of: 28-stock-chart).
- Время — секунды мастер-трека образца с двумя знаками; музыкальное место — «такт.доля» с единицы (59.1 = первая доля 59-го такта). Ключи JSON — по-английски, тексты — на языке проекта.
- Папка блока: library/raw/NN-slug/, пока у блока нет чертежа; с чертежом блок переезжает в library/ready/NN-slug/. Внутри: clip.mp4 — блок со звуком мастер-трека, запас по 1 с на вход и выход; passport.jpg — кадр в пике блока (уровень 1); frames/ — кадры для карточки, 2 кадра/с, имя f_<секунды>_b<такт.доля>.jpg, и sheet.jpg — их лист; audio.json — срез карты песни от такта до блока до такта после и звуковые теги; card.json — карточка (уровень 2); frames-hi/, sheets-hi/ и blueprint.md — чертёж (уровень 3).
- Индекс library/blocks.json — строка на блок: id, имя, время, папка, статус (passport → card → blueprint); после шага 6 — вся карточка (schema "block-card/1"); по нему ищем блоки. library/README.md — то же для человека. В доке библиотеки человек видит каталог (паспорта и главные теги) и чертежи выбранных блоков; карточки целиком живут файлами.

Шаги разбора одного блока:
1. Границы: кандидаты — из детектора склеек (ffmpeg scdet) и листов 1 кадр/с; точная граница — первый кадр нового блока, проверенный по кадрам 30 к/с. Анимированный переход (точка света, зум сквозь окно) относим к блоку, в который он ведёт.
2. Кадры: ffmpeg с подписью «время трека · такт.доля» на каждом кадре (двоеточия в drawtext экранировать), запас 1 с до и после блока; лист — ffmpeg tile.
3. Паспорт: кадр в пике (полностью собранная композиция) + строка в каталог.
4. Звуковые теги считает скрипт из карты песни → audio.json (правила ниже). Агент их не угадывает.
5. Карточка: агент получает библию стиля, словарь тегов, sheet.jpg и audio.json и пишет card.json — видеотеги по кадрам, смысловые теги по кадрам и звуковому контексту до / во время / после. Смысл строки — пересказом, без цитат.
6. Проверка и слияние: скрипт сверяет card.json со схемой (обязательные поля, теги только из словаря, уникальные id, variant_of существует) и пересобирает library.json и library.md.
7. Чертёж (только для блоков из раскадровки): кадры 4 к/с (10 к/с для быстрой типографики), листы по 20–24 кадра → blueprint.md: таблица «такт.доля · время · что происходит · звук», вид (фон, персонажи, шрифты, цвета, камера), правила синхрона, адаптация и план сборки. Образец — чертёж блока 30 в доке библиотеки.

Звуковые теги (считаются за время блока и за 1 такт до и после):
- section — раздел под серединой блока (на стыке — оба);
- voice — по доле времени: bot или main ≥ 50 %, both — каждый ≥ 25 %, none — вокала < 20 %, spoken — говорок по карте;
- energy 1–5 — медиана кратковременной громкости по пятым долям всего трека;
- length_bars, in, out — длина и точки входа и выхода в «такт.доля»;
- cut_in, cut_out — на что попадает склейка: downbeat, beat (±70 мс от доли), word (±150 мс от начала фразы), free;
- voice_lead — на сколько секунд голос блока начинается раньше картинки (бот в блоке 30 — 2.6 с);
- before, after — те же признаки для такта до и такта после.
То, что скрипт не различает (второй голос под первым), помечается в поле unsure и уточняется у человека на слух.

## Подключаемые наборы правил
Общий вид и качество задаёт не только образец, но и наборы правил — навыки или файлы инструкций. Они подключаются при настройке проекта (шаг 1) и записываются в brief.json с названием и версией.

| Набор | Что задаёт | Шаги | Для FRACTERA |
| --- | --- | --- | --- |
| Качество движения | камера, глубина и планы, свет и материалы, вес и инерция, типографика в действии, motion blur и глубина резкости, звук и SFX, раскадровка до реализации, итерации с честными статусами, проверка и экспорт | 9, 12–16 | vizavi-motion 1.6.1 (zip от заказчика) |
| Визуальный стиль проекта | герой, объёмные стилизованные формы, перспектива, мягкий свет, осмысленная камера, палитра, движок рендера | 4, 9, 13–14 | fractera-lego-motion |
| Песня | ТЗ на трек, дуэт, разметка для генератора, замер | 3, 8, 10–11 | fractera-song |
| Бренд | логотип, цвета, тон, запреты, правила для чужих брендов и персонажей | все | бренд-гайды заказчика |
| Образец | библия стиля и библиотека блоков | 4–6, 9 | разбор LGTM |

- Без набора качества движения фазу D не начинаем: если у заказчика нет своего, предлагаем известный (например, vizavi-motion) и согласуем.
- Порядок при конфликте: бриф и слова заказчика → бренд → стиль проекта → качество движения → библия стиля образца. Пример: образец плоский, а стиль проекта объёмный 3D — побеждает стиль проекта, из образца берём грамматику (ритм, типографику, режимы).
- То, что наборы задают по-разному, решается в брифе явно: fps (vizavi-motion по умолчанию 60, наш пробный рендер — 30), разрешение, длительность.
- Набор ставится навыком (в Claude Code — в .claude/skills проекта) или кладётся файлом в project/rules/.

## Конвейер: 4 фазы, 16 шагов, 6 утверждений

Фаза A — заказ
1. Бриф и наборы правил: заполнить бриф и подключить наборы (раздел «Подключаемые наборы правил»). → brief.json. ✓ Утверждение 1.
2. Образец: файлы видео и отдельно аудио в лучшем качестве. Записи экрана свести с треком по звуку (кросс-корреляция огибающих) и найти дыры в покрытии. → source/, alignment.json.

Фаза B — разбор образца (параллельно с фазой A)
3. Звук: замер — сетка долей, разделы и повторы, голоса и их доли, громкость, границы фраз. → song-map.json, song_map.png.
4. Стиль: библия стиля по контакт-листам (1 кадр/с); до карточек, потому что она задаёт общий словарь. → style-bible.md.
5. Нарезка на блоки и паспорта: детектор склеек + контакт-листы + ручная правка (анимированные переходы детектор не видит). → library/raw/NN-slug/ (раздел «Разбор блока», шаги 1–3).
6. Карточки блоков: агенты параллельно, потом один проход слияния (повторы → один блок с вариациями). (раздел «Разбор блока», шаги 4–6) → card.json, blocks.json, README.md. ✓ Утверждение 2 (стиль и библиотека).

Фаза C — сочинение вместе с заказчиком
7. Интервью: заказчик рассказывает историю и ценность клипа, свободно (текст или голосовое), и отдаёт тезисы, фрагменты слов, произношение. Пересказать ему историю в 3–5 строках, спросить только то, без чего нельзя начать (не больше 5 вопросов), согласовать. → story.md, phrases.md (дословно).
8. Форма песни (ТЗ на трек, модуль песни): разделы, такты, роли голосов, место бренд-слова. → song-spec.md.
9. Раунды раскадровки (см. «Как идут раунды») до тех пор, пока все сцены не согласованы. → док «Раскадровка», storyboard.json, changelog. ✓ Утверждение 3: раскадровка заморожена.
10. Текст с разметкой для генератора музыки — собирается из колонки слов замороженной раскадровки, роль перед каждой строкой, произношение заказчика переведено в нотацию (растяжки многоточием, акцент капсом, повторы). → lyrics.txt, style-prompt.txt.
11. Музыка: 3–4 генерации, замер каждой по ТЗ, человек слушает лучшие по замеру, починка отдельных разделов. → song.wav, карта нашей песни. ✓ Утверждение 4 (песня).
12. Перетайминг и аниматик: сцены раскадровки кладём на настоящие такты и слова песни, собираем черновой ролик 480p из кадров блоков и наших текстов; короткий раунд правок по таймингу. → animatic.mp4, timeline.json. ✓ Утверждение 5.

Фаза D — производство
13. Чертежи блоков, вошедших в раскадровку (раздел «Разбор блока», шаг 7). → blueprint.md; блок переезжает в library/ready/NN-slug/.
14. Сцены: каждая — код в движке с чистой функцией времени renderAt(t), по чертежу и таймингу слов нашей песни; агенты параллельно по сценам; проверочные кадры на ключевых долях. → scenes/<id>/.
15. Монтаж и рендер: timeline.json → рендер кусками → склейка → звук. → final_16x9.mp4.
16. Проверка и выдача: синхрон текста с голосом (±1 кадр), бренд, отсутствие ассетов образца, громкость, кодек; проверяет агент, не участвовавший в производстве. Затем Shorts 9:16 из сильных кусков, обложка, субтитры. → out/. ✓ Утверждение 6.

## Как идут раунды раскадровки (шаг 9)
Раунд — одна версия дока «Раскадровка» (все версии в одном доке, история сохраняется). В нём:
- история в 3–5 строках, как мы её поняли;
- таблица сцен по форме песни: № · раздел и такты · голос · слова (черновик; слова заказчика помечены и неприкосновенны) · что в кадре · блок-образец · статус (черновик / есть вопрос / согласовано — выпадающий список);
- лента — одна картинка с кадрами блоков по порядку сцен;
- не больше 5 вопросов к заказчику и список «что изменилось с прошлого раунда».
Заказчик идёт по сценам: комментирует строку в доке (или пишет в чат «сцена 7: …») и сам ставит «согласовано». Мы читаем комментарии, меняем только несогласованные сцены, отвечаем в ветке комментария, что сделали, и выпускаем следующую версию. Согласованную сцену трогаем, только если заказчик сам её открыл. Стоп: все сцены «согласовано» → заморозка. После генерации музыки слова меняются только через замену раздела и новый замер.
Второй цикл согласования — на аниматике (шаг 12): только тайминг и картинка, слова уже заморожены.

## Поля карточки кратко (полный формат и пример — в разделе «Разбор блока»)
- id, name; source: t0, t1, такты, раздел песни.
- audio_context — звук до / во время / после блока (предыдущая фраза, фраза под блоком, следующая): раздел, кто поёт, энергия, смысл строки своими словами.
- voice, lyric_role, function, mode, energy, text_density, motion.
- params — что заменяемо: тексты, числа, цвета, иконки.
- build — route, difficulty, assets; adaptation — как блок служит бренду; repeats — где повторяется и чем отличается вариация.

## Словарь тегов (расширять только через библию стиля)
- section: intro, verse, pre, chorus, post, break, bridge, build, outro
- voice: main, bot, both, spoken, none
- lyric_role: illustrates, counterpoint, title, transition
- function: hook, setup, explain, list, metric, dialogue, reveal, transition, punchline, credits
- mode: из библии стиля (у текущего образца: dark-terminal, light-slide, red-incident; у нас ещё 3d)
- energy: 1–5; bars_class: 1, 2, 4, 8
- cut: downbeat, beat, word, free
- motion: из словаря движений библии стиля (light-dot-in, type-on, strike, handwrite, slam, flip, hop, dolly, zoom-through, particles, glitch-out…)
- route: 2d, 3d, mixed

## Агенты
- Параллельно только независимая работа: карточки (шаг 6), чертежи (шаг 13), сцены (шаг 14), независимая проверка (шаг 16). Раунды раскадровки ведёт один агент — тот, кто разговаривает с заказчиком.
- Каждому агенту — одинаковые библия стиля и словарь тегов, свой срез карты песни и кадры своего блока.
- После параллельной работы — один проход слияния и сверки.

Библиотека блоков — главный накопленный актив: каждый разобранный образец её пополняет.

## Среда и сроки
- Производство — в Claude Code на Mac или на сервере: ffmpeg; Python (librosa, onnxruntime, scikit-learn, matplotlib); Node + Playwright с настоящим Chrome и GPU для рендера; Claude in Chrome — превью, визуальная проверка и сайт Suno; Suno MCP (бета), если есть доступ. Раунды раскадровки — в доке Claude Docs: заказчик комментирует с телефона.
- Тайминг слов нашей песни — от генератора, если он его отдаёт, иначе локальным распознаванием речи (например, Whisper) по известному тексту.
- Измеренные скорости (облако, 2 ядра, без GPU): рендер ≈ 0.9 с на кадр 1080p (5 мин при 30 fps ≈ 2–2.5 ч); отделение вокала 5-минутного трека ≈ 6 мин. На Mac с GPU рендер в разы быстрее.

## Как это станет элементом Fractera (после первого полного прогона)
Кандидат в custom element (WEB4 ITEM) из fractera-custom-item-starter:
- рабочая природа в паспорте: принимает бриф, историю и файлы образца; отдаёт клип 16:9, Shorts 9:16, песню и пополнение библиотеки блоков;
- A2A-задачи: «разобрать образец», «сделать клип», «нарезать Shorts»;
- внутри: этот навык и модули, процесс рендера (Chrome + ffmpeg), библиотека — через data-элемент узла, вход — через auth-элемент;
- страницы: бриф и интервью, раунды раскадровки с комментариями по сценам, шесть утверждений, просмотр аниматика и финала, библиотека блоков.
Сначала один полный прогон на ролике FRACTERA с замером времени и узких мест каждого шага, потом ТЗ на элемент.
